# 后端逐文件函数导航

> 本文是 `backend/README.md` 中架构地图的函数级补充，按 `backend/app/` 的生产源码逐文件盘点。包含私有辅助函数、类方法、接口路由和仅定义模型/常量的文件；不枚举 `backend/tests/` 测试用例。

## 阅读路径

```text
app/main.py：创建应用并初始化共享服务
  → api：接收 HTTP/SSE 请求，校验数据并调用服务
  → services：编排聊天、资料导入、评估和检索实验业务
      → rag：问题改写、向量检索、证据判断和回答生成
      → repositories：将业务记录读写到 SQLite
      → 文件存储 / FAISS / 外部模型 Provider
  → schemas：约束请求与响应的数据结构
```

`main.lifespan()` 在启动时初始化数据库并创建服务单例，放入 `app.state`；`api/dependencies.py` 再从请求上下文取出这些服务。API 路径实际挂载在 `settings.api_prefix` 下。SQLite 保存文档、分块和任务等业务记录；FAISS 是可由成功分块重建的向量索引。

## 逐文件索引

### 应用入口

#### `app/main.py`

**文件职责：** 创建 FastAPI 应用，管理服务生命周期、中间件、路由和异常处理。

- `lifespan()`：初始化数据库和业务服务，并在应用运行期间维持服务上下文。

- `PATCH /retrieval-strategies/{id}` · `update_retrieval_strategy()`：更新策略配置并记录新版本。

### 核心基础设施

#### `app/core/__init__.py`

**文件职责：** 声明后端核心基础设施包，包含配置、数据库和错误处理模块。

- 本文件不定义函数或类；仅声明包入口、导出、常量或模型辅助信息。

#### `app/core/config.py`

**文件职责：** 集中声明环境变量配置、默认值、校验规则及项目路径解析。

- **类 `Settings`：** 应用运行配置；字段可由对应的大写环境变量覆盖。
  - `require_api_embedding_settings()`：校验切分、检索参数之间的约束及 API 嵌入所需配置。
  - `database_path()`：将 SQLite URL 解析为数据库文件路径，保留内存数据库标记。
  - `embedding_model()`：返回当前 Provider 实际使用的嵌入模型名称。
  - `faiss_path()`：返回相对于项目根目录解析后的 FAISS 索引目录。
  - `upload_path()`：返回相对于项目根目录解析后的上传文件目录。
  - `builtin_document_path()`：返回相对于项目根目录解析后的内置文档目录。
  - `_project_path()`：将相对路径锚定到项目根目录，绝对路径保持不变。

#### `app/core/database.py`

**文件职责：** 负责 SQLite 连接、数据库初始化、迁移以及就绪状态检查。

- `initialize_database()`：创建数据库目录、启用外键并执行建表脚本和兼容性迁移。
- `_migrate_document_schema()`：升级文档表结构，使其支持 Markdown、内置来源标识及来源去重。
- `_migrate_message_schema()`：为旧消息表增加可空 AI 模式字段，保留已有会话数据。
- `_migrate_citation_schema()`：为旧引用表补充轻量检索评分、证据来源和锚点信息。
- `_migrate_evaluation_schema()`：升级评估运行、结果、用例及运行快照相关表结构。
- `_migrate_retrieval_strategy_schema()`：为检索策略补充版本、启用状态及版本历史表。
- `_migrate_retrieval_experiment_schema()`：为旧检索实验表补充归档状态并创建归档查询索引。
- `_table_columns()`：读取指定 SQLite 表的全部列名。
- `database_is_ready()`：通过轻量查询确认配置的 SQLite 数据库当前可连接。

#### `app/core/error_codes.py`

**文件职责：** 集中定义 API 业务错误码，供服务层和接口层统一返回错误标识。

- **类 `ErrorCode`：** 跨接口稳定使用的业务错误码枚举。

#### `app/core/errors.py`

**文件职责：** 定义应用级异常类型，并将异常统一转换为 API 响应。

- **类 `AppError`：** 携带稳定业务错误码、用户提示和 HTTP 状态的应用异常。
  - `__init__()`：初始化业务异常及其 API 响应信息。
- `_error_body()`：构造所有错误响应共用的 code/message/data 外层结构。
- `register_exception_handlers()`：在 FastAPI 应用中注册业务、校验、HTTP 和未预期异常处理器。
  - `handle_app_error()`：将 AppError 转换为统一错误结构，并保留异常携带的 HTTP 状态码。
  - `handle_validation_error()`：将请求校验失败转成统一响应，并为检索实验配置错误选择专用错误码。
  - `handle_http_error()`：将 Starlette HTTP 异常转换为统一响应，保留原 HTTP 状态码和响应头。
  - `handle_unexpected_error()`：记录异常堆栈和请求 ID，返回不泄漏内部细节的通用 500 响应。

### RAG 与模型接入

#### `app/rag/__init__.py`

**文件职责：** 声明检索增强生成（RAG）组件包及其公共导出。

- 本文件不定义函数或类；仅声明包入口、导出、常量或模型辅助信息。

#### `app/rag/ai_modes.py`

**文件职责：** 定义聊天和离线 RAG 作业共用的 AI 模式推理参数配置。

- **类 `AiModeProfile`：** 描述 AI 模式在证据判断和答案生成阶段的推理设置。

#### `app/rag/chains.py`

**文件职责：** 组合查询改写、检索、证据核验和答案生成等 RAG 执行链。

- **类 `RagChain`：** 组合问题改写、证据判断和最终回答三个阶段的 LangChain Runnable。检索结果由 RetrievalService 提供，模型按阶段参数配置，因而同一条链可以被生产问答与实验预览复用。
  - `__init__()`：初始化问答链及其检索、模型和提示词依赖。
  - `_set_chat_models()`：根据运行配置创建并设置各阶段所需的聊天模型。
  - `set_chat_model()`：将同一个聊天模型实例绑定到改写、证据判断和回答阶段，供旧接口或显式单模型调用方继续使用；各阶段仍按当前配置分别应用采样参数。
  - `rewrite_question()`：根据聊天上下文生成适合检索的改写问题。
  - `retrieve()`：执行问题检索并返回候选证据。
  - `judge_evidence()`：判断候选证据是否足以支持针对用户问题的回答。
  - `answer_prompt_value()`：构造包含问题、历史消息和证据的最终回答提示。
  - `complete_answer()`：调用回答模型生成完整答案。
  - `stream_answer()`：以流式方式生成答案并逐段产出内容。
  - `answer_messages()`：渲染最终答案链所需的消息序列，并把问题、证据、回答风格、合规提示及工具结果填入对应模板；此方法只准备模型输入，不执行生成。
- `_evidence_from_document()`：将检索到的 LangChain 文档转换为证据响应字典。
- `_answer_prompt()`：构造生成最终答案时使用的提示模板。
- `_rewrite_prompt()`：构造将用户问题改写为检索查询时使用的提示模板。
- `_evidence_prompt()`：构造判断检索证据是否充分时使用的提示模板。
- `_escape_fstring_literals()`：转义字符串模板中的花括号，避免被误解析为格式占位符。
- `_format_evidence()`：将证据列表格式化为模型可读的文本块。
- `_tool_result()`：把工具调用结果转换为提示词中的展示文本。
- `_format_points()`：将预期要点列表格式化为文本。
- `_evidence_judgement()`：调用模型判断当前证据能否支持回答。
- `_failed_closed_judgement()`：构造保守拒答的证据判定结果。
- `_parse_evidence_judgement()`：解析并校验模型生成的证据判定结构。
- `_message_dicts()`：将消息对象转换为角色与文本组成的字典列表。
- `_answer_input()`：组装生成回答所需的上下文和工具数据。
- `_refusal()`：返回证据不足时使用的拒答文案。

#### `app/rag/embeddings.py`

**文件职责：** 封装文本嵌入模型的创建、调用、校验及可用性处理。

- **类 `EmbeddingProvider`：** 数据类型或协议声明；具体字段和继承关系请查看源码定义。
  - `embed_documents()`：协议方法：批量接收文档文本并返回一一对应的嵌入向量。
- **类 `_LangChainEmbeddingProvider`：** 把底层 LangChain Embeddings 统一适配为项目的嵌入 Provider，并记录 Provider、模型、归一化设置和首次计算出的向量维度，供索引签名校验使用。
  - `__init__()`：初始化嵌入适配器及其配置或底层 Provider。
  - `embed_documents()`：将一组文档文本编码为向量列表。
  - `embed_query()`：将单条查询文本编码为向量。
- **类 `_LazyEmbeddings`：** 延迟创建底层嵌入模型：应用初始化时只保存工厂函数，第一次执行文本或查询向量化时才创建模型，并缓存实例供后续调用复用。
  - `__init__()`：初始化嵌入适配器及其配置或底层 Provider。
  - `inner()`：按需创建并缓存底层嵌入模型实例。
  - `embed_documents()`：将一组文档文本编码为向量列表。
  - `embed_query()`：将单条查询文本编码为向量。
- **类 `LangChainEmbeddingService`：** 为 LangChain 向量流程提供统一嵌入入口。默认按 Settings 延迟构建本地或远程 Provider，并在输出处校验、归一化向量及记录维度；显式传入 Provider 的入口供离线维护和确定性测试使用。
  - `__init__()`：初始化嵌入适配器及其配置或底层 Provider。
  - `embedding_dimension()`：返回当前嵌入模型已知的向量维度。
  - `embed_documents()`：将一组文档文本编码为向量列表。
  - `embed_query()`：将单条查询文本编码为向量。
  - `signature()`：生成用于识别当前嵌入配置的签名信息。
- `_validate_texts()`：校验待嵌入文本列表非空且内容有效。
- `_validate_vectors()`：校验向量数量、维度和数值类型。
- `_normalize()`：对输入向量进行归一化处理。

#### `app/rag/errors.py`

**文件职责：** 定义 RAG 组件内部可识别的模型和嵌入异常类型。

#### `app/rag/providers.py`

**文件职责：** 创建并检查聊天模型、嵌入模型等外部 Provider。

- `build_chat_model()`：根据应用配置构造 OpenAI 兼容的 LangChain 聊天模型。
- `_deepseek_thinking_options()`：把产品推理设置转换为 DeepSeek 兼容的模型请求参数。
- `build_embeddings()`：按配置创建本地或远程的 LangChain 文本嵌入实现。
- `_resolve_local_model()`：优先使用本地模型路径，否则查找 Hugging Face 本地缓存。
- `local_embedding_is_cached()`：检查当前配置的本地嵌入模型是否已在本机缓存。
- `_resolve_local_device()`：将 auto 设备设置解析为当前机器可用的 CUDA、MPS 或 CPU。
- `_configure_local_torch_runtime()`：应用 macOS 下避免 PyTorch 与 FAISS OpenMP 冲突的线程配置。
- **类 `CompatibleEmbeddings`：** 直接向 OpenAI 兼容嵌入端点提交文本并返回向量。
  - `__init__()`：保存远程嵌入请求所需的模型、凭证、端点和可选客户端。
  - `endpoint()`：返回最终嵌入请求 URL。
  - `embed_documents()`：批量请求文本向量并按原始输入顺序返回。
  - `embed_query()`：将单条查询文本转换为向量。
- `_without_endpoint_suffix()`：规范化基础 URL，并移除已存在的指定 endpoint 后缀。

#### `app/services/vector_store.py`

**文件职责：** 管理向量索引的创建、加载、更新、检索和签名兼容性。

- **类 `EmbeddingSignatureProvider`：** 向量签名提供方协议，供索引服务在不依赖特定嵌入实现的情况下取得模型兼容性标识。
  - `signature()`：协议方法：根据已知或待探测的向量维度构造嵌入模型签名。
- **类 `VectorStoreError`：** 向量索引读写或检索流程的业务异常基类，供调用方统一捕获向量库相关故障。
- **类 `VectorStoreNotInitialized`：** 表示请求检索时尚未加载或构建 FAISS 索引；调用方可据此返回知识库未就绪状态。
- **类 `VectorStoreSignatureMismatch`：** 表示磁盘索引记录的嵌入模型签名与当前配置不一致；阻止使用维度或模型语义不同的向量进行检索。
  - `__init__()`：初始化向量签名不匹配异常并保留当前索引元数据。
- **类 `VectorStorePersistenceError`：** 表示索引文件或元数据读取、写入、替换失败；保留为独立异常类型，便于 API 层区分存储故障和普通检索错误。
- **类 `_UnavailableEmbeddings`：** 在调用方已经提供预计算向量、无需文本编码时作为 Embeddings 占位实现；若误触发文本嵌入则立即报错，避免静默生成无效数据。
  - `embed_documents()`：将文本列表编码为向量。
  - `embed_query()`：将查询文本编码为向量。
- **类 `VectorStoreService`：** 将持久化 FAISS 索引包装为 LangChain VectorStore，同时保留项目的签名校验、原子文件替换和生命周期管理。索引中的 Document 只保存稳定分块 ID，正文与来源字段仍以 SQLite 为准。
  - `__init__()`：初始化向量存储及索引目录、嵌入模型和锁。
  - `meta()`：返回当前 FAISS 索引元数据。
  - `status()`：计算向量索引的当前就绪状态。
  - `is_ready()`：判断向量索引是否已加载且可检索。
  - `load()`：从磁盘读取 FAISS 索引与元数据，并校验二者及当前嵌入签名是否匹配；索引文件尚不存在时返回 False，避免把首次启动误报为损坏。
  - `is_signature_compatible()`：比较现有索引和当前嵌入配置是否兼容。
  - `add()`：保留旧调用方一次提交分块及预计算向量的兼容入口；新导入流程优先使用 add_documents，由嵌入服务生成并校验向量。
  - `add_documents()`：实现 LangChain 文档写入契约：接受调用方提供的向量或通过当前嵌入服务计算向量，补齐稳定分块元数据后更新并持久化索引。
  - `add_texts()`：实现 LangChain VectorStore 的文本插入接口，将文本、元数据和可选 ID 转换为 Document 后交给统一写入路径处理。
  - `from_texts()`：实现 LangChain 标准工厂接口：先用给定 Embeddings 生成文本向量，再创建带项目持久化配置的向量库实例并写入索引。
  - `similarity_search()`：按查询文本执行相似度检索。
  - `similarity_search_with_score()`：执行相似度检索并返回分数。
  - `similarity_search_by_vector()`：按已计算的查询向量执行相似度检索。
  - `similarity_search_with_score_by_vector()`：按查询向量检索并返回相似度分数。
  - `_document_with_score()`：将检索分数写入文档元数据并返回副本。
  - `_index_ids()`：读取 FAISS 索引中保存的文档标识。
  - `_document_for_chunk_id()`：构造指定文本块对应的最小文档对象。
  - `_normalize_document()`：规范化文档元数据并确保包含分块标识。
  - `_document_chunk_id()`：从文档元数据解析有效的文本块标识。
  - `_build_langchain_store()`：构造与当前 FAISS 索引关联的 LangChain 包装器。
  - `_add_with_documents()`：将文档和向量写入 FAISS 并更新索引元数据。
  - `remove()`：删除指定文本块对应的向量索引项。
  - `search()`：执行向量相似度检索并映射为应用证据结构。
  - `_search_without_openmp()`：在 macOS 上隔离小型索引的 FAISS 搜索调用，避免与 PyTorch 加载的另一套 OpenMP 运行时竞争线程资源。
  - `save()`：将当前向量索引和元数据持久化到磁盘。
  - `rebuild_from_success_chunks()`：仅从数据库中已成功导入的文本块重新生成向量，并用新的嵌入签名构建完整索引；完成后原子替换旧索引，避免读到半成品。
  - `_signature_for()`：根据向量维度创建当前嵌入签名。
  - `_new_meta()`：创建描述当前索引状态的元数据对象。
  - `_same_embedding_signature()`：判断两个嵌入签名是否完全一致。

  - `_persist()`：将指定索引和元数据原子持久化。
